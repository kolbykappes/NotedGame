# <Project> workflow, scope and documentation duties

The kit's "definition of done" includes the project's documentation duties. They live here.

## Scope guardrails

- What is in scope, what is explicitly out, and what needs a plan before building (save/load, networking, and so on).
- Preferred slice order for features.

## Research duty (the kit's "research before craft")

- Research folder, file naming (one file per topic) and where it is indexed. What each file must contain.

## Backlog and changelog

- Where the to-do list lives and the fields an item needs. Where completed work is logged and what a log line contains.
- Which status or build-state doc must be kept current, and when.

## Other documentation duties

- Anything else that must be updated in the same change as the code (playbooks, asset provenance, release notes).
